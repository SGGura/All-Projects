# TETRIS 240x320 — игра для экрана 240×320 без тача

Игра под портретный TFT 240×320 (ILI9341 / ST7789 / ST7789V и подобные),
управление **только физическими кнопками**. Тач, мышь и указатель не
используются нигде — ни в игре, ни в симуляторе.

Тетрис выбран потому, что портретное соотношение 240×320 — это ровно
пропорция стакана 10×20: поле занимает 140×280 px, а справа остаётся
полноценная панель 80 px под NEXT, HOLD, счёт, уровень и линии. Плюс игра
полностью управляется пятью кнопками и не требует ни диагоналей, ни
прицеливания.

## Что внутри

* Вращение по **SRS** с полным набором wall kick'ов (отдельные таблицы для I).
* **7-bag** генератор — не бывает шести S-ок подряд.
* **Ghost piece** — контур в месте приземления.
* **HOLD** — отложить фигуру, один раз на фигуру.
* **Lock delay** 500 мс с 15 сбросами: фигуру можно доводить после касания.
* **DAS/ARR** (170 / 45 мс) — удержание кнопки едет плавно, одиночное нажатие
  двигает ровно на клетку.
* Мягкий и жёсткий сброс, комбо, back-to-back за тетрис, 20 уровней скорости.
* Рекорд с флагом «пора сохранить», чтобы не тереть EEPROM каждый кадр.

Ядро — обычный C99: **нет malloc, нет float, нет libc, нет LVGL и GUI_GSP**.
Оно ничего не знает ни про панель, ни про кнопки.

## Управление

| Кнопка | Действие | Клавиша в симуляторе |
|---|---|---|
| LEFT / RIGHT | движение | ← → |
| UP | поворот по часовой | ↑ |
| DOWN | мягкий сброс | ↓ |
| A | жёсткий сброс, «подтвердить» | Space или Z |
| B | HOLD *(необязательная кнопка)* | C или Left Shift |
| START | пауза *(необязательная кнопка)* | Enter или P |

Минимум — **5 кнопок** (LEFT, RIGHT, UP, DOWN, A): игра полностью
проходится, недоступны только HOLD и пауза.

## Сборка симулятора

```bash
sudo apt install -y build-essential cmake pkg-config libsdl2-dev
cd TETRIS_GAME
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/tetris_sdl --scale 3     # окно 720x960, картинка 240x320 без сглаживания
./build/tetris_sdl --demo        # играет встроенный бот (демо-режим)
```

Окно — попиксельная копия панели: игра рисует в буфер 240×320 RGB565, который
отдаётся в текстуру `SDL_PIXELFORMAT_RGB565` как есть. Выход — Escape.

Симулятор не только опрашивает состояние клавиатуры раз в кадр, но и
защёлкивает нажатия из очереди событий: иначе тап короче 16 мс терялся бы
между опросами. На железе это тоже стоит иметь в виду, если опрос кнопок
редкий.

## Тесты

`tetris_shots` — headless-харнесс: играет ботом из `src/bot.c` (оценка стакана
по высоте, дыркам, неровности и числу собранных линий), проверяет инварианты и
сохраняет PNG. Ни дисплея, ни SDL не требует, поэтому годится для CI.

```bash
./build/tetris_shots build/shots
ctest --test-dir build
```

Проверяется в том числе, что **отрисовка полосами даёт ровно тот же кадр**,
что и отрисовка целиком, — это важно для портов на МК с малым ОЗУ (см. ниже).

## Портирование на железо

Нужны три вещи.

**1. Инициализация**

```c
tetris_init(seed, load_highscore_from_eeprom());
```

`seed` должен отличаться от запуска к запуску, иначе каждая партия будет
одинаковой. Подойдёт значение свободно бегущего таймера в момент первого
нажатия кнопки или показания АЦП на неподключённом входе.

**2. Опрос кнопок и такт логики**

Маска — уровень, а не фронт: бит выставлен всё время, пока кнопка нажата.
Фронты, автоповтор и тайминги игра считает сама, порту остаётся только
антидребезг.

```c
static uint32_t read_buttons(void)
{
    uint32_t b = 0;
    if (!HAL_GPIO_ReadPin(BTN_GPIO, PIN_LEFT))  b |= BTN_LEFT;   /* кнопка на землю */
    if (!HAL_GPIO_ReadPin(BTN_GPIO, PIN_RIGHT)) b |= BTN_RIGHT;
    if (!HAL_GPIO_ReadPin(BTN_GPIO, PIN_UP))    b |= BTN_UP;
    if (!HAL_GPIO_ReadPin(BTN_GPIO, PIN_DOWN))  b |= BTN_DOWN;
    if (!HAL_GPIO_ReadPin(BTN_GPIO, PIN_A))     b |= BTN_A;
    return b;
}

/* простейший антидребезг: бит принимается, когда совпал N опросов подряд */
static uint32_t debounce(uint32_t raw)
{
    static uint32_t last, stable;
    static uint8_t  count;

    if (raw != last) { last = raw; count = 0; }
    else if (count < 3) { if (++count == 3) stable = raw; }
    return stable;
}
```

**3. Кадр**

```c
static uint16_t line_buf[240 * 40];          /* 19 КБ вместо 150 КБ */
static gfx_t g = { line_buf, 240, 40, 0, 0 };

for (;;) {
    tetris_tick(millis(), debounce(read_buttons()));

    for (int y = 0; y < 320; y += 40) {
        g.y_off = y;
        tetris_render(&g);                   /* координаты остаются экранными */
        tft_blit(0, y, 240, 40, line_buf);   /* окно памяти панели + поток пикселей */
    }

    if (tetris_take_highscore_dirty())
        save_highscore_to_eeprom(tetris_highscore());
}
```

Ключевой момент — поля `x_off` / `y_off` в `gfx_t`. Буфер может покрывать
только полосу экрана, при этом весь код рисования продолжает работать в
экранных координатах, а всё лишнее отсекается. Так что кадр можно собирать
полосами любой высоты: 40 строк — 19 КБ, 8 строк — 3,8 КБ, целиком — 150 КБ.
Харнесс проверяет, что результат побайтово совпадает с полным кадром.

Формат пикселя — RGB565, как у ILI9341/ST7789 в режиме 16 бит. Если панель
ждёт big-endian (а большинство именно так), либо включите аппаратный
байтсвоп SPI/DMA, либо переверните байты в `tft_blit`.

### Требования к ресурсам

| | |
|---|---|
| Код (gcc `-Os`, x86-64) | ≈ 10 КБ, на Cortex-M ощутимо меньше; `bot.c` в это не входит и на устройстве не нужен |
| ОЗУ игры | ≈ 0,6 КБ статически, динамической памяти нет |
| Буфер кадра | от 3,8 КБ (полоса 8 строк) до 150 КБ (весь экран) |
| Такт | `tetris_tick()` раз в ~16 мс; всё завязано на метку времени, так что более редкий цикл просто менее плавный |

Ядро не использует деление в горячем пути, float и рекурсию, поэтому
спокойно живёт на Cortex-M0 и на PIC32.

### Экран другого размера

Разметка в `src/tetris.c` собрана из констант в начале файла: `CELL`,
`FIELD_X`, `FIELD_Y`, `PANEL_X`, `PANEL_W`. Например, для 320×240 (альбомная
ориентация) достаточно уменьшить `CELL` до 11 и сдвинуть панель.

### Настройка ощущений от управления

Всё в начале `src/tetris.c`:

| Константа | По умолчанию | Смысл |
|---|---|---|
| `DAS_MS` | 170 | задержка перед автоповтором сдвига |
| `ARR_MS` | 45 | период автоповтора |
| `SOFT_DROP_MS` | 45 | скорость мягкого сброса |
| `LOCK_DELAY_MS` | 500 | время до фиксации после касания |
| `gravity_ms[]` | 800…35 | скорость падения по уровням |

Таблица гравитации намеренно мягче гайдлайна: на кнопках без DAS-тренировки
20G неиграбельны.

## Отношение к остальному репозиторию

Проект самостоятельный. `GUI_GSP` — это библиотека виджетов для монохромных
дисплеев 128×64 с 1 бит на пиксель, для цветного тетриса она не подходит.
`DINO_GAME` собран на LVGL 9 + SDL2 и рассчитан на тач. Здесь нет ни того,
ни другого: только собственный слой рисования и кнопки.
