# DOOM-240 — техническое задание

Псевдо-3D шутер (рейкастер в стиле Wolfenstein 3D) для встраиваемого устройства.
Документ самодостаточен: по нему игру можно реализовать с нуля без дополнительного контекста.

---

## 1. Целевая платформа

| Параметр | Значение |
|---|---|
| МК | PIC32MZ2048EFH (MIPS M-Class, 200–252 МГц, аппаратный FPU, 2 МБ Flash, 512 КБ ОЗУ) |
| Тулчейн | MPLAB X + XC32, C99 |
| Дисплей | TFT 240×320 (портрет), RGB565 |
| GUI | LVGL 8.x (`LV_COLOR_DEPTH 16`) |
| Ввод | 5 аппаратных кнопок, тача нет |
| Хост-проект | прошивка прибора (MPLAB X проект `TPro.X`); игра — один из «экранов» меню |

Дополнительно нужен SDL-симулятор для ПК (см. §10), чтобы отлаживать игру без железа.

---

## 2. Жанр и цель игры

Игрок ходит по лабиринту от первого лица, стреляет по монстрам, подбирает аптечки
и патроны. Цель — дойти до выхода живым. Псевдо-3D: рейкастинг по сетке
(один луч на столбец экрана), враги и предметы — масштабируемые по дистанции спрайты.

Состояния игры: `TITLE` (заставка) → `PLAY` → `DEAD` («YOU DIED») или `WIN`
(«LEVEL CLEARED» + статистика). Из `DEAD`/`WIN` кнопкой FIRE — снова `TITLE`/`PLAY`.

---

## 3. Компоновка экрана (240×320, портрет)

```
┌──────────── 240 px ────────────┐
│  потолок (тёмный градиент)     │  ▲
│    стены: вертикальные полосы, │  │
│    высота = f(дальности),      │  │ 240 px — 3D-вид
│    текстура + затемнение       │  │
│    спрайты врагов/предметов    │  │
│    прицел (центр), пистолет    │  │
│  пол (градиент, светлее к низу)│  ▼
├────────────────────────────────┤
│ HP 100   AMMO 40   KILLS 0/12  │  ▲ 80 px — HUD
│ ██████░░ (полоса здоровья)     │  ▼
└────────────────────────────────┘
```

- 3D-вьюпорт: 240×240, горизонт на y=120. FOV ≈ 66°.
- HUD: панель 240×80 внизу: HP (число + красная полоса), AMMO, KILLS x/y.
- Эффекты: красная вспышка всего вьюпорта при уроне (~200 мс), жёлтая при подборе
  предмета, вспышка и отдача пистолета при выстреле.
- Прицел: маленький белый крест в центре вьюпорта.

## 4. Управление (5 кнопок)

| Кнопка | В игре | На заставке / экранах смерти и победы |
|---|---|---|
| UP | шаг вперёд | — |
| DOWN | шаг назад | — |
| LEFT | поворот влево | — |
| RIGHT | поворот вправо | — |
| FIRE | выстрел | старт / рестарт |

Кнопки удерживаемые (состояние «нажата/отпущена»), не события.

## 5. Механика и баланс

| Параметр | Значение |
|---|---|
| Игрок | 100 HP, 40 патронов на старте, скорость 3.0 клетки/с, поворот 2.4 рад/с, радиус коллизии 0.22 |
| Выстрел игрока | hitscan по центральному лучу, урон 34±8, кулдаун 0.3 с, попадание если враг в конусе прицела и ближе стены |
| Имп (8 шт. на карте) | 60 HP, скорость 1.6 кл/с, ближний бой: дистанция <1.3, урон 8±6, кулдаун 0.9 с |
| Солдат (4 шт.) | 100 HP, скорость 1.1 кл/с, стреляет с дистанции до 10 клеток при прямой видимости, кулдаун 1.4 с, шанс попадания 0.7 − 0.05·дист (мин. 0.2), урон 5±8 |
| ИИ врагов | спят, пока нет прямой видимости игрока ближе 8 клеток (или пока не получат урон); проснувшись — преследуют (движение по осям с «скольжением» вдоль стен); короткий стан (~0.25 с) при попадании |
| Аптечка (3 шт.) | +25 HP (максимум 100), подбор при дистанции <0.6 |
| Патроны (3 шт.) | +12 патронов, подбор при дистанции <0.6 |
| Труп | убитый враг остаётся плоским спрайтом-трупом, не мешает проходу |
| Победа | коснуться клетки выхода `X` |
| Поражение | HP ≤ 0 |

## 7. Архитектура кода

Игровое ядро — **чистый C99 без зависимостей от LVGL и HAL** (только stdint/stdbool/
string/math). Оно рендерит кадр в предоставленный извне буфер RGB565 240×320
(row-major, `index = y*240 + x`). Обвязка (LVGL-канвас, опрос кнопок, SDL-симулятор) —
отдельные файлы.

Файлы:

- `game.h` / `game.c` — ядро (карта, физика, ИИ, рейкастер, HUD, состояния);
- `main.c` — SDL-симулятор для ПК;
- на стороне прошивки — небольшой модуль-экран, создающий `lv_canvas` и гоняющий тики.

### Контракт API (game.h)

```c
#define GAME_W 240
#define GAME_H 320

typedef enum {
    GAME_KEY_UP = 0, GAME_KEY_DOWN, GAME_KEY_LEFT,
    GAME_KEY_RIGHT, GAME_KEY_FIRE, GAME_KEY_COUNT
} game_key_t;

void game_init(uint16_t *framebuffer);          /* буфер 240*320, владеет вызывающий */
void game_set_key(game_key_t key, bool pressed);/* текущее состояние кнопки */
void game_tick(uint32_t dt_ms);                 /* логика + рендер одного кадра */
```

Требования к ядру:

- никакой динамической аллокации (всё статическое);
- никаких собственных прерываний/таймеров — время приходит параметром `dt_ms`
  (клампить до 50 мс);
- `float` разрешён (у EF-серии аппаратный FPU); внутренние циклы отрисовки текстур —
  на целочисленной арифметике (fixed point 16.16);
- опция `-DGAME_COLOR_SWAP=1`: после рендера кадра один проход байт-свопа
  (для дисплеев с `LV_COLOR_16_SWAP 1`).

## 8. Рендеринг

1. **Стены — рейкастинг DDA** (классический алгоритм lodev): на каждый из 240
   столбцов один луч; `perpWallDist` → высота полосы `240/dist`; выборка столбца
   текстуры 64×64 (или 32×32) с шагом fixed-point; затемнение полосы по дальности
   (`shade = clamp(256 − dist·13, 32, 256)`, применяется к RGB565 поканально)
   и дополнительное ×0.7 для граней N/S против E/W.
2. **Пол/потолок** — по градиентной таблице цветов на строку (предвычислена),
   без текстурирования.
3. **Z-буфер** — массив `float zbuf[240]` дальностей стен по столбцам.
4. **Спрайты** (враги, трупы, предметы): сортировка по дальности (дальние раньше),
   проекция в экранные координаты, масштаб = `240/dist·scale`
   (враги scale 0.75, предметы и трупы 0.4), нижняя кромка прижата к полу,
   прозрачный цвет-ключ 0xF81F, отрисовка столбцами с проверкой z-буфера.
5. **Пистолет** — спрайт внизу по центру вьюпорта; при выстреле сдвиг (отдача)
   и жёлтая вспышка у дула.
6. **HUD и тексты** — свой мини-шрифт 5×7 (столбцовая упаковка, A–Z, 0–9,
   немного знаков), масштабируемый целым множителем. Никаких шрифтов LVGL.
7. Прототипу разрешено генерировать текстуры/спрайты процедурно при инициализации;
   финальная версия должна уметь брать их из Flash (см. §9) — формат хранения
   одинаковый, меняется лишь источник указателя.

Опция на случай нехватки ОЗУ/FPS: компайл-тайм флаг половинного разрешения —
рендер в 120×160 с программным удвоением пикселей при выводе.

## 9. Графические ресурсы во Flash

- Все картинки хранятся во **внутренней** программной Flash как `const uint16_t`
  массивы RGB565 (XC32 кладёт `const` в Flash автоматически; чтение при включённом
  prefetch-кэше достаточно быстрое для попиксельной выборки).
- Прозрачность спрайтов — цвет-ключ `0xF81F` (magenta), без альфа-канала.
- Набор: 5–8 текстур стен 64×64 (~40–65 КБ); спрайты импа и солдата по 2–4 кадра
  64×64 (~100–130 КБ); труп, аптечка, патроны, пистолет 2 кадра (~20–30 КБ).
  Итого ~200 КБ из 2 МБ.
- Конвертация PNG → C-массив: LVGL Image Converter (True color, RGB565) или
  простой скрипт. Внешнюю SPI-flash для текстур не использовать —
  попиксельное чтение по SPI на каждом кадре недопустимо медленно.

## 10. SDL-симулятор (ПК)

- Окно 240×320 (масштаб ×2), LVGL 8.3 + `lv_canvas`, флаш в SDL-текстуру.
- Клавиши: стрелки/WASD — движение, Space/Ctrl — огонь, Esc — выход.
- Headless-режим (`--headless`): без окна прогнать скриптованную сессию
  (заставка → старт → проход вперёд → повороты → выстрелы) и сохранить
  BMP-скриншоты кадров — для автотестов и проверки рендера без дисплея.
- Сборка CMake; LVGL подтягивать FetchContent'ом (tag v8.3.x).

## 11. Интеграция в прошивку (MPLAB X, LVGL 8)

```c
static lv_color_t game_fb[GAME_W * GAME_H];   /* 150 КБ ОЗУ */

/* вход в игру из меню прибора: */
lv_obj_t *cv = lv_canvas_create(lv_scr_act());
lv_canvas_set_buffer(cv, game_fb, GAME_W, GAME_H, LV_IMG_CF_TRUE_COLOR);
game_init((uint16_t *)game_fb);

/* в главном цикле, пока игра активна: */
game_set_key(GAME_KEY_UP,    key_up_held());
game_set_key(GAME_KEY_DOWN,  key_down_held());
game_set_key(GAME_KEY_LEFT,  key_left_held());
game_set_key(GAME_KEY_RIGHT, key_right_held());
game_set_key(GAME_KEY_FIRE,  key_fire_held());
game_tick(dt_ms);            /* dt от системного мс-таймера */
lv_obj_invalidate(cv);
lv_timer_handler();
```

- Выход из игры (например, длинное удержание DOWN+FIRE или отдельная кнопка
  прибора) — удалить канвас и вернуть прежний экран LVGL.
- На время игры не запускать длинные блокирующие операции прошивки.
- Проверить бюджет ОЗУ по `.map`: игре нужно ~160 КБ (буфер + состояние).
  Если не влезает — включить половинное разрешение (§8), буфер 37.5 КБ.

## 12. Порядок работ и критерии приёмки

Этапы:

1. Ядро `game.c` + SDL-симулятор, процедурные текстуры; проверка в headless-режиме.
2. Балансировка (скорости, урон, расстановка врагов) в симуляторе.
3. Замена процедурной графики на `const`-массивы во Flash (формат §9).
4. Интеграция в проект прошивки: экран-обёртка, кнопки, вход/выход из игры.
5. Профилирование на железе; при необходимости — половинное разрешение,
   оптимизация внутренних циклов.

Приёмка:

- игра проходима от старта до выхода `X`; смерть и рестарт работают;
- стабильные ≥20 FPS на целевом железе при полном разрешении
  (или ≥30 при половинном);
- ядро собирается XC32 без предупреждений, ОЗУ по `.map` в пределах бюджета;
- прошивка прибора вне игры работает без изменений поведения.
