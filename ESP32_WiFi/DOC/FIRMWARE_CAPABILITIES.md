# Возможности ESP-AT SPI Wi‑Fi модуля

## 1. Назначение

Эта прошивка превращает модуль **ESP8684-MINI-1-H2X**
(ESP32-C2, Flash 2 МБ) в универсальный сетевой Wi‑Fi-сопроцессор для приборов с хост-контроллером.

Хост-контроллер прибора является SPI Master. Модуль ESP является SPI Slave,
принимает текстовые AT-команды и передаёт контроллеру ответы и сетевые данные.
Прикладная логика прибора остаётся в хост-контроллере.

Собранный профиль:

- платформа: ESP32-C2;
- модуль: `ESP32C2-MINI-1-H2X-SPI`;
- ESP-AT: `v5.1.0.0-dev`;
- Flash: 2 МБ;
- основной интерфейс AT: только SPI;
- Wi-Fi OTA: отключено.

## 2. Подключение к главному контроллеру

| Сигнал | GPIO ESP8684 | Назначение |
|---|---:|---|
| SCLK | GPIO6 | Тактирование от SPI Master |
| MOSI | GPIO7 | Данные от хоста к ESP |
| MISO | GPIO2 | Данные от ESP к хосту |
| CS | GPIO10 | Выбор ESP |
| HANDSHAKE | GPIO3 | ESP сообщает о готовности транзакции |
| UART0 TX | GPIO8 | Только диагностический лог |
| UART0 RX | GPIO9 | Только диагностическая консоль |

Параметры рабочего SPI-интерфейса:

- Standard SPI, одна линия MOSI и одна MISO;
- SPI mode 0;
- ESP работает как Slave;
- интерфейс полудуплексный на уровне протокола ESP-AT;
- каждая транзакция инициируется главным контроллером;
- линии command, address и dummy имеют по 8 бит;
- внутренний DMA-блок ESP: до 4092 байт;
- входной и выходной stream buffer: по 2048 байт;
- рекомендуемая частота SPI: до 40 МГц после проверки разводки.

Главный контроллер обязан обслуживать `HANDSHAKE`, номера последовательности,
длину передачи и направления Master-to-Slave/Slave-to-Master по протоколу
Espressif SPI AT. Обычной отправки строки непосредственно в SPI без реализации
этого транспортного протокола недостаточно.

## 3. Wi-Fi

Поддерживаются:

- режим Station (STA): подключение прибора к существующей точке доступа;
- режим SoftAP: прибор создаёт собственную точку доступа;
- совместная работа STA + SoftAP;
- сканирование доступных сетей;
- подключение и отключение от точки доступа;
- DHCP-клиент и DHCP-сервер SoftAP;
- получение IP, маски, шлюза и MAC-адреса;
- автоматическое повторное подключение;
- сохранение параметров подключения в NVS;
- WPS;
- SmartConfig;
- IPv4;
- IPv6 и автоматическая IPv6-конфигурация;
- SNTP для получения времени из сети.

Типовые AT-команды: `AT+CWMODE`, `AT+CWLAP`, `AT+CWJAP`,
`AT+CWQAP`, `AT+CWSAP`, `AT+CIFSR`, `AT+CWAUTOCONN`.
Конкретный формат параметров следует сверять с документацией той версии
ESP-AT, из которой собран проект.

## 4. TCP/IP и сокеты

Прошивка поддерживает:

- TCP-клиент;
- TCP-сервер;
- UDP;
- SSL/TLS-клиент;
- SSL/TLS-сервер;
- одиночное и многоканальное соединение;
- до **5 AT-соединений** одновременно;
- DNS-разрешение имён;
- Ping;
- прозрачный режим передачи для одного соединения;
- пассивный и активный режим приёма сетевых данных;
- IPv4 и IPv6.

Основные команды семейства: `AT+CIPSTART`, `AT+CIPSEND`,
`AT+CIPCLOSE`, `AT+CIPSTATUS`, `AT+CIPMUX`, `AT+CIPSERVER`,
`AT+CIPMODE`, `AT+CIPRECVMODE`, `AT+CIPRECVDATA`,
`AT+CIPDOMAIN`, `AT+PING`.

Сокеты подходят для:

- существующих собственных TCP/UDP-протоколов;
- отправки измерений;
- удалённого управления;
- связи с локальным сервером;
- самостоятельной реализации прикладного протокола на хосте.

## 5. HTTP и HTTPS

Включён встроенный HTTP-клиент ESP-AT. Главный контроллер может выполнять
HTTP-запрос без ручного формирования TCP-сеанса и HTTP-заголовков.

Поддерживаются:

- HTTP GET;
- HTTP POST;
- HTTPS GET;
- HTTPS POST;
- получение размера ресурса;
- передача URL, заголовков и тела запроса;
- получение кода состояния и тела ответа.

Основные команды семейства: `AT+HTTPCLIENT`, `AT+HTTPGETSIZE`,
`AT+HTTPCGET`, `AT+HTTPCPOST`.

Размеры внутренних HTTP-буферов:

- TX: 2048 байт;
- RX: 2048 байт.

Большой ответ не следует считать целиком помещающимся в RAM контроллера.
Хост должен принимать и обрабатывать данные порциями.

HTTP Basic Auth и Digest Auth в данной сборке не включены.

## 6. TLS

Поддерживаются защищённые TCP/HTTPS-соединения и следующие варианты
аутентификации:

- сервер проверяет клиента;
- клиент проверяет сервер;
- взаимная проверка сертификатов;
- PSK.

В прошивке присутствует системный набор корневых сертификатов. При этом
конфигурация также разрешает соединение без проверки сертификата сервера.
В серийном изделии необходимо явно выбрать требуемый режим проверки и не
использовать небезопасный режим для соединений через Интернет.

Размеры TLS-записей:

- вход: до 16384 байт;
- выход: до 4096 байт.

## 7. mDNS / Bonjour

mDNS включён и совместим с Apple Bonjour. Команда `AT+MDNS` позволяет
опубликовать устройство и сервис в локальной сети.

Например, прибор может быть доступен как:

- имя: `device.local`;
- сервис: имя сервиса прибора;
- порт: TCP-порт сервиса прибора.

Это позволяет приложению найти прибор без знания его IP-адреса.
Встроенная AT-команда предназначена прежде всего для публикации собственного
сервиса. Если прибор должен искать произвольные Bonjour-сервисы, браузер mDNS
нужно реализовать на главном контроллере через UDP multicast.

## 8. Системные функции

Доступны:

- проверка связи командой `AT`;
- получение версии через `AT+GMR`;
- программный перезапуск;
- восстановление заводских параметров;
- сохранение настроек в NVS;
- энергосбережение и light sleep;
- пользовательские AT-команды ESP-AT;
- команды пробуждения главного контроллера;
- диагностические signaling-команды.

UART0 GPIO8/GPIO9 предназначен для диагностики. Рабочие AT-команды хоста
должны передаваться через SPI.

## 9. Отключённые функции

Для уменьшения размера прошивки отключены:

- MQTT AT;
- WebSocket AT;
- файловая система AT;
- встроенный Web Server;
- Wi-Fi OTA;
- BLE;
- BluFi;
- Wi-Fi Enterprise/EAP;
- Ethernet;
- специальные AT-команды драйверов.

MQTT и WebSocket при необходимости можно реализовать на главном контроллере
поверх TCP/TLS или позднее включить соответствующие модули ESP-AT.

## 10. Производительность

При SPI 40 МГц Standard Mode ориентировочная полезная скорость TCP:

- хост -> ESP -> Wi-Fi: около 1.0–1.37 МБ/с;
- Wi-Fi -> ESP -> хост: около 1.0–1.30 МБ/с.

Это приблизительно 8–11 Мбит/с в одном направлении. Реальный результат
зависит от точки доступа, уровня сигнала, режима AT, размера блоков,
скорости обработки SPI главным контроллером и использования TLS.

Для максимальной скорости следует:

- передавать данные крупными блоками;
- быстро обслуживать `HANDSHAKE`;
- не задерживать чтение входящих данных;
- использовать прозрачный режим там, где он подходит;
- избегать мелких `CIPSEND`;
- проверить целостность сигнала SPI на 40 МГц.

## 11. Рекомендуемая последовательность запуска

1. Подать питание и снять ESP с Reset.
2. Инициализировать SPI mode 0 и вход `HANDSHAKE`.
3. Дождаться готовности ESP-AT.
4. Отправить `AT` и проверить ответ `OK`.
5. Запросить `AT+GMR` и проверить совместимую версию.
6. Выбрать режим STA, SoftAP или STA+SoftAP.
7. Настроить или восстановить параметры сети.
8. Дождаться получения IP-адреса.
9. При необходимости опубликовать сервис mDNS.
10. Запустить TCP/UDP/TLS-соединения либо выполнить HTTP GET/POST.
11. Постоянно обрабатывать асинхронные сообщения и входящие данные ESP.

Драйвер хоста не должен ожидать только ответ на последнюю команду: ESP-AT
может асинхронно сообщать о подключении Wi-Fi, выдаче IP, закрытии сокета и
приходе сетевых данных.

## 12. Обновление прошивки

Обновление через Wi-Fi отключено. Команды Wi-Fi OTA в сборку не входят.
Обновлением управляет хост-контроллер прибора.

Важно: рабочий протокол SPI AT и режим программирования внутренней Flash
ESP32-C2 — разные интерфейсы. Запись образа не выполняется AT-командами через
рабочий SPI AT. Для обновления с главного контроллера нужен отдельный
реализованный на хосте загрузчик/программатор, который переводит ESP в ROM
download mode и записывает подготовленный образ поддерживаемым способом.

Готовый полный образ:

`build/factory/factory_ESP32C2-MINI-1-H2X-SPI.bin`

Размер полного образа: 2 МБ. Он записывается с адреса `0x0`.

## 13. Ограничения ресурсов

- Flash модуля: 2 МБ.
- Размер app-раздела: `0x130000` (1 245 184 байта).
- Размер текущего приложения: 1 061 472 байта.
- Свободно в app-разделе: 183 712 байт, около 15%.
- AT-соединений: максимум 5.
- Сокетов lwIP: максимум 16, часть занята внутренними сервисами.
- SPI stream buffers: 2048 + 2048 байт.
- HTTP buffers: 2048 + 2048 байт.

При добавлении MQTT, WebSocket или других крупных функций необходимо повторно
проверить размер приложения, RAM и устойчивость при нескольких соединениях.
